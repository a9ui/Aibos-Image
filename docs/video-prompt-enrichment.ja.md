# 動画のAI補完

動画メニューの「AIで動きの細部を補完」は、スタイル本文と選択した動作を、
元画像の姿勢に合う動き方へ具体化します。大きさ・速さ・移動距離・回数・感情の
強さを上げる機能ではありません。「軽く跳ぶ」を大ジャンプに変えず、膝の準備、
着地、服や髪の収まり方などを補います。手動の腕・表情・カメラ指定を優先します。
補う必要がなければ、追加しない結果も正常です。

キューには先に登録します。ローカルAIは、そのジョブの順番が来て動画生成を
始める直前に実行します。AI補完を外した動画は従来どおり直接生成します。
AIの返答に時間指定や書式の不整合がある場合は、一度だけ補正を試みます。
適用できなければ、元の本文と適用済みの手動設定で動画生成を続け、診断に記録します。
AI補完に失敗したことだけで動画ジョブ全体を失敗扱いにはしません。
独自の本文形式をAI補完が読み取れない場合も、音声のOFF指定を伴わなければ
補完を省いて元の本文で続けます。元画像・実行環境・中止状態の確認は保持します。

## 設定

- **PNGの生成プロンプトも参考にする**：元画像の正の生成プロンプトを補助情報に
  使います。最大2,000文字を登録時に固定し、元画像・今回の本文・手動選択を優先
  します。ネガティブプロンプト、ワークフロー、日本語の説明欄は送りません。
  読めない場合は参考情報なしです。OFFの場合も条件判定を明示的に有効にした
  スタイルのローカル条件評価は別に行いますが、PNG本文をAIの参考資料には送りません。
- **今回のセリフ・BGMを指定する**：既定はOFFで、本文の音声指定を維持します。
  ONではセリフとBGMを個別に選択します。元のスタイルは変更しません。
- **セリフ**：既存のセリフがあれば、その言葉と言語タグ・話者を保持します。
  発話や無言の指定がない場合に限り、画像と本文に合う短い日本語を補います。
  自由文の発話と動作が分離できない場合、OFFは曖昧な箇所の診断を返します。
  文全体を削除したり、追加の禁止文だけで矛盾が解決した扱いにはしません。
- **セリフの量**：新規のセリフだけに適用する上限です。少なめ・中間・多めは
  動画尺の約18%・34%・50%を発話時間の予算とし、短い動画では行数も減らします。
  日本語1文字につき200msと1行400msの余裕を見積もり、前後に間を確保します。
  これは保守的な計画用の目安で、実際の音声長を測定した値ではありません。
- **BGM**：本文にある背景音楽を保持、または未指定の背景音楽を補います。
  OFFではBGM欄を `N/A` にします。環境音や動作音を一緒に消しません。
- **重力・接触・動きのつながり**：画像で分かる支持・接触を守り、既存の動きの
  慣性や収束を言葉で補います。物理シミュレーターではなく、LoRAの適用でもありません。

## H3への組み立て

[MiniMaxの公式ガイド](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_base_en.md)
に沿う短い書式ガイドを、画像解析のたびにローカルAIへ渡します。
AIが返すのは本文の要約ではなく、短い細部・候補番号・新規セリフ・背景音楽です。
Aibosが0秒の元画像参照文、映像、環境音、BGMの順序を組み立てます。
新規セリフの話者、表情、発声、口の動きはタグの外に置き、タグ内は
`<d>[Japanese]こんにちは。</d>` のような発話内容だけにします。
時間帯は動作・発話の計画であり、フレーム単位の強制制御ではありません。

元本文は約900文字へ圧縮しません。最終本文全体の8,000文字上限は保持し、
上限を超える場合も元本文を切り詰めません。本文の意味が変わらないという
数学的な保証はなく、映像モデルの動作遵守や口と声の完全同期も保証しません。

新規ジョブは版2の契約を使います。既存の版1の待機ジョブは元の経路のままで、
再試行でも同じ登録内容を使用します。新しい方式を既存ジョブへ勝手に適用しません。
詳細な形式は `contracts/enhancement-video-prompt-enhancement-v2.json` と共有検証例を参照してください。
